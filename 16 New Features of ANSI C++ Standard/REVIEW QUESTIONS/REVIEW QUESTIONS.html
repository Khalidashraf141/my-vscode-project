16.1 List the two data types added by the ANSI C++ standard committee.

The ANSI C++ standard committee added the following two data types:

  1. bool
    • Used to represent Boolean values
    • Can store only true or false
  1. wchar_t
    • Used to represent wide characters
    • Supports extended character sets (Unicode/ wide characters)

16.2 State application of bool type variables.

The bool data type is used to store logical values true or false.

Its main applications are:

  1. Decision making in conditional statements such as if , if-else , and switch
  1. Controlling loops like while for and do-while
  1. Storing results of relational and logical expressions
  1. Returning logical status from functions (success/failure)
  1. Using flags to control program flow

16.3 Review the need for wchar_t character type.

The wchar_t character type was introduced to support wide characters that cannot be represented using the ordinary char type.

The char data type is limited to one byte and is sufficient only for basic ASCII characters.

However, many language require large character sets such as Unicode

The wchar_t type provides a larger storage size (typically 2 or 4 bytes) to represent extended and international characters.

Thus, wchar_t is needed for internationalization, multilingual applications, and Unicode character handling in ANSI C++.

16.4 List the new operators added by the ANSI C++ standard committee.

The ANSI C++ Standard Committee added the following new operators to provide type safety and runtime information:

  1. static_cast
  1. const_cast
  1. reinterpret_cast
  1. dynamic_cast
  1. typeid

These operators replace unsafe C-style casts and help in performing controlled and meaningful type conversions in C++ programs.

16.5 Rewrite the application of const_cast operator.

The const_cast operator is used to add or remove const and volatile qualifiers from a variable.

Its main applications are:

  1. Removing const qualification from a pointer or reference when the original object is non-const
  1. Passing const data to legacy functions that do not accept const parameters
  1. Modifying object qualifiers without changing the object type
  1. Interfacing with C libraries that do not support const correctness

16.6 Explain the need of the operator static_cast while the old style cast does the same job.

Although the old C-style cast can perform type conversion, it is unsafe and unclear because it can perform multiple kinds of conversions without restriction. The static_cast operator was introduced to provide type safety and clarity in type conversion.

The need for static_cast is explained as follows:

  1. Improves type safety

    static_cast allows only well-defined and meaningful conversions and prevents many unsafe conversions that are allowed by C-style casts.

  1. Better readability and clarity

    It clearly indicates the programmer’s intention, making the code easier to understand and maintain.

  1. Compile-time checking

    Most errors are detected at compile time, reducing runtime errors.

  1. Controlled conversion

    It is mainly used for conversions between related data types such as numeric types and based-derived class pointers (without runtime checking).

  1. Avoids accidental misuse

    Unlike old-style casts, it cannot remove const or perform reinterpretation of unrelated types.

  1. Basic type conversion

Old-style cast

int a = 10;
double b = (double)a;  // old C-style cast

static_cast

int a = 10;
double b = static_cast<double>(a);  // new C++ style

Both work

static_cast is clearer and safer

  1. Pointer conversion (Base↔Derived)
class Base{};
class Derived : public Base{};

Old-style cast (Unsafe)

Base* b = new Derived;
Derived* d = (Derived*)b;  // no check, unsafe

static_cast (Restricted)

Base* b = new Derived;
Derived* d = static_cast<Derived*>(b);  // allowed but explicit

static_cast makes the conversion visible and intentional

  1. Removing const (Not allowed in static_cast)
const int x = 10;

Old-style cast (Dangerous)

int* p = (int*)&x;  // allowed, unsafe

static_cast (Compile-time error)

int* p = static_cast<int*>(&x); // ERROR
  1. Unrelated pointer conversion
int a = 10;

Old-style cast

char* p = (char*)&a; // allowed, unsafe

static_cast

char* p = static_cast<char*>(&a);  // ERROR

Blocks meaningless conversions

16.8 Extend about dynamic casting. Also explain how it is achieved in C++

The dynamic_cast operator is used for safe runtime type conversion in polymorphic class hierarchies.

It mainly converts base class pointers or references into derived class pointers or references by checking the object’s actual type at runtime.

Unlike static_cast , dynamic_cast performs runtime checking and ensures that the conversion is valid and safe.

Need for dynamic_cast

  1. To avoid unsafe downcasting (base↔derived)
  1. To ensure that the object being pointed to is actually of the target derived type
  1. To prevent runtime errors caused by invalid casts
  1. To support Runtime Type Information (RTTI)

Conditions for using dynamic_cast

  1. The base class must contain at least one virtual function
  1. It works only with pointers and references
  1. RTTI must be enabled by the compiler (enabled by default)

How dynamic casting is achieved in C++

Dynamic casting is achieved using Runtime Type Information (RTTI)

When a class contains a virtual function, the compiler creates a virtual table (vtable).

Each object of such a class contains a vptr pointing to the vtable.

During dynamic_cast:

  • The runtime system checks the actual object type using RTTI
  • If the conversion is valid, the cast succeeds
  • If invalid:
    • Pointer cast returns NULL
    • Reference cast throws std::bad_cast exception

Example Code

#include <iostream>
using namespace std;

class Base {
public:
    virtual void show() { }
};

class Derived : public Base {
};

int main() {
    Base* b = new Derived;

    Derived* d = dynamic_cast<Derived*>(b);

    if (d)
        cout << "Cast successful";
    else
        cout << "Cast failed";

    return 0;
}

Difference in behavior

  • Pointer casting → returns NULL if cast fails
  • Reference casting → throws an exception if cast fails

16.9 Outline typeid operator and its usage.

The typeid operator is used to obtain type information of an object or expression at runtime.

It is a part of Runtime Type Information (RTTI) in ANSI C++ and returns a reference to an object of type type_info

Need for typeid

The typeid operator is required to:

  • Identify the actual data type of an object during program execution
  • Support runtime type checking
  • Assist in debugging and type comparisons in polymorphic programs

Code Example

#include <iostream>
#include <typeinfo>
using namespace std;

class Base {
public:
    virtual void show() { }
};

class Derived : public Base {
};

int main() {
    Base* b = new Derived;

    cout << typeid(*b).name();

    return 0;
}

The presence of a virtual function ensures correct runtime type detection.

Important Points

  • If used with a polymorphic object, typeid returns the derived type
  • If used with a non-polymorphic object, it returns the static type
  • Requires inclusion of <typeinfo>

16.10 Describe explicit conversion and how it is performed it C++

Explicit conversion is a type conversion in which the programmer intentionally specifies the target data type.

It is used when automatic (implicit) conversion is not allowed or not safe.

In C++, explicit conversion is performed using cast operators that clearly indicate the type of conversion to be carried out.

Ways of Performing Explicit Conversion in C++

  1. C-style cast (Old method)
int a = 10;
double b = (double)a;
  1. C++ cast operators (Preferred method)
    • static_cast
    • const_cast
    • reinterpret_cast
    • dynamic_cast
int a = 10;
double b = static_cast<double>(a);

16.11 Recall the use of keyword mutable.

The keyword mutable is used to allow a data member of a class to be modified even when the object is declared as const.

Normally, const objects do not permit modification of their data members, but mutable provides an exception to this rule

Used of mutable keyword

  1. Allows modification of specific data members inside const member functions
  1. Used for caching values, logging, or reference counting
  1. Helps maintain logical constness of an object
  1. Does not affect the physical constness of other data member

Example Code

class Sample {
    mutable int count;
public:
    Sample() : count(0) {}

    void display() const {
        count++;   // allowed because count is mutable
    }
};

16.12 Review namespace conflict and its handling in C++.

A namespace conflict occurs when two or more identifiers (such as variables, functions, or classes) have the same name and are defined in different scopes or libraries, causing ambiguity for the compiler.

C++ introduces namespace to avoid such naming conflicts and to organize large programs.

Causes of Namespace Conflict

  1. Same function or variable names in different libraries
  1. Large programs developed by multiple programmers
  1. Use of common or generic identifier names

Handling Namespace Conflict in C++

  1. Using Scope Resolution Operator(::)

    Allows explicit access to a particular namespace.

    std::cout << "Hello";
  1. Using using Declaration

    Imports a specific name from a namespace

    using std::cout;
  1. Using using Directive

    Imports all members of a namespace (use with caution).

    using namespace std;
  1. Creating User-defined Namespaces

    Helps organize code and avoid clashes

    namespace MySpace{
		int x;
}

16.13 State the method to access the variables declared in a named namespace.

The variables declared in a named namespace can be accessed in C++ using the following methods:

  1. Using the scope resolution operator (::)
    namespace A{
		int x = 10;
}
int main(){
		cout << A::x;
}
  1. Using using declaration
    using A::x;
cout << x;
  1. Using using directive
    using namespace A;
cout << x;

16.14 Outline namespace and differentiate between using the using namespace directive and using the using declaration for accessing namespace members.

A namespace is a declarative region that provides a scope for identifiers such as variables, functions, and classes.

Namespace are used in C++ to avoid name conflicts, organize code, and improve program readability, especially in large projects.

Using using namespace Directive

  • Imports all members of a namespace into the current scope
  • May cause name conflicts
  • Less safe in large programs

using namespace std;

Using using Declaration

  • Imports only specific members of a namespace
  • Reduces chances of name conflicts
  • Safer and more controlled

using std::cout;

16.15 Review the error in the following code segment:

const int m = 100;
int *ptr = &m;

The error in the given code is due to violation of const correctness.

Here, m is declared as constant integer (const int).

This means its value cannot be modified after initialization.

However, ptr is declared as a pointer to non-const int (int *).

Assigning the address of a const int to a non-const pointer is not allowed in C++, because it may allow modification of a constant object through the pointer.

Hence, the compiler generates an error.

Correct Code

const int m = 100;
const int *ptr = &m; // correct

Now, ptr is pointer to a constant integer, so the value of m cannot be modified through ptr.

16.16 Discover the problem with the following statements:

const int m = 100;
double *ptr = const_cast<double*>(&m);

The given code has multiple serious problems related to type safety and illegal casting.

  1. const_cast cannot change data type

    The const_cast operator is used only to add or remove const or volatile qualifiers.

    It cannot covert one data type to another (from int to double).

  1. Invalid pointer type conversion

    The address of an int object is being converted to a double* , which is not allowed and leads to undefined behavior

  1. Violation of const correctness

    The object m is declared as const. Any attempt to modify it through a pointer (even after casting) results in undefined behavior.

  1. Compilation error

    The code will not compile, because const_cast does not permit changing the underlying type.

16.18 Analyze the correctness of the following namespace definition

namespace Main
{
int main()
{
// ....
}
}

The given namespace definition is syntactically correct, but it is logically incorrect according to the C++ program execution rules.

In C++, the function main() must be defined in the global namespace.

The C++ standard specifies that program execution always starts from ::main()

Placing main() inside a namespace (such as Main) makes it inaccessible to the runtime system as the program entry point.

Therefore, the program will compile successfully, but it will fail to link or execute properly, because the required global main() function is missing.

namespace Main(){
	void run(){
	}
}
int main(){
		Main::run();
}
