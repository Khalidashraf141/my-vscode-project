16 New Features of ANSI C++ Standard

ANSI and ISO in C++

  • ANSI (American National Standards Institute)
    • Early standardization of C and initial C++
    • ANSI C → C89 / C90
    • No longer maintains C++ standards
  • ISO (International Organization for Standardization)
    • Current and official authority for C++
    • All modern C++ versions are ISO standards
    • Examples: C++11, C++14, C++17, C++20
  • Important Point
    • C++ is an ISO standardized language

explicit Keyword

  • Used with single-argument constructors
  • Prevents implicit type conversion
  • Improves code safety and clarity
explicit Test(int x);
  • Disallows:
Test t = 5; // error

mutable Keyword

  • Allows a data member to be modified inside:
    • const member function
    • const object
  • Used for:
    • counters
    • caches
    • internal state changes
mutable int count;

wchar_t Data Type

  • Introduced in ANSI C++
  • Stores wide characters
  • Size: 16 bits (2 bytes) (traditional explanation)
  • Used for languages with larger character sets
    • Japanese
    • Chinese
    • Korean

Wide Character Literal

  • Represents a wide character
  • Begins with L
  • Used two bytes of memory

wchar_t ch = L'A';

char Character Type

  • Size: 1 byte (8 bits)
  • Can represent 256 different values (0-255)
  • Suitable for English characters
  • Uses numeric character codes (ASCII)

bool Data Type

  • Stores logical values:
    • true
    • false

Implicit Conversion to bool

  • Allowed from:
    • integer
    • floating-point
    • pointer

Conversion Rules

  • 0 0.0 nullptr → false
  • Any non-zero value → true

	bool x = 0; //false
	bool y = 100; // true
	bool z = 15.75; // true
In C++, zero is false and non-zero is true

NEW OPERATORS

static_cast Operator in C++

static_cast is a C++ type-casting operator used to convert one data type into another at compile time.

It performs no runtime checking. The compiler assumes that the programmer knows what they are doing.

In C++:

  • Implicit conversions are sometimes not allowed
  • C-style casts are unsafe and unclear

static_cast provides:

  • Safer and clearer casting than C-style casts
  • Controlled type conversion
  • Better readability

Syntax

static_cast<new_type>(expression)

Where static_cast is used

  1. Primitive type conversion
int a = 10;
double b = static_cast<double>(a);
  • Converts int to double safely
  • Happens at compile time
  1. Upcasting (Derived → Base) → ALWAYS SAFE
class Person{};
class Student : public Person{};

Student s;
Person* p = static_cast<Person*>(&s);
  1. Downcasting (Base —> Derived) — RISKY
class Person{
public:
		virtual ~Person(){}
};

class Student : public Person{};

Person* p = new Student();
Student* s = static_cast<Student*>(p); // works, but no check
  • Works only if object is actually Student
  • Dangerous if object is not Student

Dangerous example (Undefined Behavior)

Person* p = new Teacher();  //object is Teacher
Student* s = static_cast<Student*>(p);  // WRONG
s->study();  // undefined behavior

Compiler does not stop you

Program may crash or corrupt memory

Why static_cast is dangerous in polymorphism

  • It does not check the actual object type
  • It blindly trusts the programmer
  • Wrong downcast leads to undefined behavior

This is why dynamic_cast exists.

When should you use static_cast

Use static_cast When:

  • You are 100% sure of the object type
  • Performance is critical
  • Casting between related types safely
  • Primitive type conversions

Avoid static_cast when:

  • Object type is unknown at runtime
  • Polymorphism is involved without certainty

static_cast is fast and efficient, but unsafe for incorrect downcasting in polymorphic class hierarchies.

const_cast Operator in C++

const_cast is a C++ casting operator used to add or remove const and/or volatile qualifiers from a variable.

It does NOT change the data type. It works with pointer and references

What const_cast can and cannot do

  • Remove const
  • Add const
  • Remove volatile

Syntax

const_cast<type>(expression)

Valid forms:

int* p = const_cast<int*>(const_ptr);
int& r = const_cast<int&>(const_ref);

Not allowed

const int a = 10;
int b = const_cast<int>(a); //Error

Reason:

  • const_cast works only on pointers or references
  • Values create copies → removing const makes no sense

Unsafe(Undefined Behavior)

const int a = 10;
int* p = const_cast<int*>(&a);
*p = 20; // undefined behavior

Reason:

  • Original object is truly const

Safe Use

int a = 10;
const int* p = &a;

int* q = const_cast<int*>(p);
*q = 20; //safe

Reason:

  • Object was NOT originally const
  • const was added later

What is volatile?

volatile tells the compiler

This variable can change at any time, outside the control of the program

So the compiler:

  • Must NOT optimize access
  • Must NOT cache the value in a register
  • Must always read from memory

Why volatile is needed

Without volatile compiler may assume:

This value never changes here

This assumption is wrong when:

  • Hardware changes the value
  • Interrupts modify the value
  • OS or signal handlers modify it

volatile is a type qualifier that prevents compiler optimizations for variables whose values may change unexpectedly outside the program flow.
  • const_cast → removes/adds const or volatile (only pointer/references)
  • Unsafe if original object is truly const
  • volatile → tells compiler “don’t optimize, value may change externally
  • volatile ≠ thread safety
  • Used heavily in embedded systems, hardware access, ISRs

dynamic_cast Operator in C++

dynamic_cast is a C++ casting operator used to perform safe type conversion at runtime in an inheritance hierarchy.

It checks the actual (runtime) type of an object before casting

If the cast is not valid:

  • For pointers → returns nullptr
  • For references → throws std::bad_cast

Why do we need dynamic_cast?

In polymorphism, we often write:

Base* b = new Derived();

At runtime, we may not know:

  • Which derived object b is pointing to

Using static_cast here is dangerous, because it does not runtime checking.

dynamic_cast solves this problem safely.

  1. Most IMPORTANT RULE
dynamic_cast works only with polymorphic classes.

This means:

Base class must have at least one virtual function

class Base{
public:
	virtual ~Base(){}
	
}

Without a virtual function → compile time error.

Syntax

dynamic_cast<new_type>(expression)
#include <iostream>
using namespace std;

class Person {
public:
    virtual ~Person() {}
};

class Student : public Person {
public:
    void study() {
        cout << "Student is studying" << endl;
    }
};

int main() {
    Person* p = new Student();

    Student* s = dynamic_cast<Student*>(p);

    if (s != nullptr) {
        s->study();   // ✅ safe
    }

    delete p;
}

Output

Student is studying

Failing Example (Safe Failure)

class Teacher : public Person {};

int main() {
    Person* p = new Teacher();

    Student* s = dynamic_cast<Student*>(p);

    if (s == nullptr) {
        cout << "Not a Student";
    }

    delete p;
}
  • Program does NOT crash
  • Cast fails safely

When should you use dynamic_cast?

Use When:

  • Runtime type is unknown
  • Polymorphism is used
  • Safety is more important than speed

Avoid when:

  • You already know the exact type
  • Performance is critical
  • No polymorphism is involved

typeid Operator in C++

What is the typeid operator?

The typeid operator is used to obtain type information of an expression at runtime.

It tells what type an object really is, especially when polymorphism is involved.

typeid is part of RTTI (Run-Time Type Information)

Why do we need typeid

In polymorphism, we often write:

Base* b = new Derived();

At compile time:

  • b is of type Base*

At runtime:

  • The actual object may be derived

typeid helps us identify the real object type at runtime.

Header File Required

#include <typeinfo>
typeid gives runtime (dynamic) type information only if the class is polymorphic

That means:

Base class must have at least one virtual function

class Base{
	public:
		virtual ~Base(){}
}

Without a virtual function → typeid gives compile-time type only.

typeid(ptr) vs typeid(*ptr)

Rule to remember:

typeid(ptr) -> static (compile-time) type
typeid(*ptr) -> dynamic (runtime) type
#include <iostream>
#include <typeinfo>
using namespace std;

class Org {
public:
    virtual ~Org() {}
};

class Dept : public Org {};

int main() {
    Dept d;
    Org* ptr = &d;

    cout << typeid(ptr).name() << endl;    // Org*
    cout << typeid(*ptr).name() << endl;   // Dept
}
  • ptr is a pointer variable
  • typeid(ptr) checks the pointer’s type → Org*
  • *ptr refers to the actual object
  • Since Org is polymorphic, RTTI is used
  • typeid(*ptr) returns the real object type → Dept

NAMESPACE SCOPE

Namespace scope means that a name (variable, function, class, etc.) is visible inside a namespace where it is defined

namespace Math{
		int value = 10;
		
		void show(){
				cout << value;
		}
}

Key points

  • value and show() belong to namespace Math
  • Outside the namespace, they are not directly accessible

❌Invalid:

cout << value;  // ERROR

✅Valid:

cout << Math::value;
Math::show();

The scope of value is the Math namespace → namespace scope

Unnamed (Anonymous) Namespace

An unnamed namespace has no name and is used to restrict visibility only to the current source file.

namespace{
		int x = 5;
		void display(){
				cout << x;
		}
}

Why use unnamed namespace?

  • Provides internal linkage
  • Similar to static at global scope
  • Prevents name conflicts across file

Key points

  • Accessible only inside the same .cpp file
  • Automatically treated as unique per file

display(); // OK (same file)

❌ From another file:

display(); // ERROR

Unnamed namespaces = file-scope protection

Qualified Name

A qualified name explicitly specifies which namespace the name belongs to using the scope resolution operator ::.

Syntax

namespace_name::identifier

Example

namespace A{
		int num = 100;
}
cout << A::num; //qualified name

Key points

  • Avoids ambiguity
  • Used when multiple namespaces have same name

namespace A{int x = 1;}
namespace B{int x = 2;}

cout << A::x; // qualified
cout << B::x; // qualified

Unqualified Name

An unqualified name is used without specifying the namespace

cout << x;  // unqualified name

When is it allowed?

If:

  • Name is in the same scope
  • using namespace is used
  • using declaration is used

Example

namespace A{
		int x = 10;
}
using namespace A;
cout << x; //unqualified name (valid)

or

using A::x;
cout << x; //unqualified

⚠️Risk:

using namespace std;
  • Can cause name clashes in large programs

OPERATOR KEYWORDS

The ANSI C++ Standard proposes keywords for several C++ operators. These keywords, can be used in place of operator symbols in expressions.

For Example:

x > y && m != 100
may be written as
x > y and m not_eq 100

Operator keywords not only enhance the readability of logical expressions but are also useful in situations where keyboards do not support certain special characters such as &, ^ and ~

#include <iostream>
#include <fstream>
