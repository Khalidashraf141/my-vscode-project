14 Introduction to the Standard Template Library

INTRODUCTION

  • The Standard Template Library (STL) is an important part of C++ that supports generic programming.
  • It provides ready-made template-based classes and algorithms that make programming easier, faster, and more efficient.
  • The STL was developed by Alexander Stepanov and Meng Lee while working at Hewlett-Packard.
  • Today, STL is a standard part of ANSI C++, and it allows programmers to store, manage, and process data without writing code from scratch.
  • In short:

    STL saves time, reduces errors, and helps programmers write clean, reusable, and efficient C++ programs.

using namespace std;

COMPONENTS OF STL

The Standard Template Library (STL) contains several components, but at its core there are three main components:

  1. Containers
  1. Algorithms
  1. Iterators

These three components work together to support a wide variety of programming solutions.

  • Containers are used to store data.
  • Algorithms are used to process or manipulate data (such as searching, sorting, etc.)
  • Iterators act like pointers and are used to access the elements stored in containers.

The relationship between these components is as follows:

Algorithms use iterators to perform operations on data stored in containers.

Thus, containers hold the data, iterators provide access to the data, and algorithms perform operations on that data.

Containers

A container is an object that stores data.

It defines how data is organized in memory

STL containers are implemented using template classes, so they can store different types of data such as int, float, char, or user-defined objects.

Examples: vector, list, set, map

Algorithms

An algorithm is a procedure used to process data stored in containers.

STL provides many algorithms for tasks such as:

  • Initializing
  • Searching
  • Copying
  • Sorting
  • Merging

STL algorithms are implemented using template functions, which makes them generic and reusable.

Iterators

An iterator is an object that works like a pointer.

it points to elements inside a container.

Using iterators, we can:

  • Move through container elements
  • Access data
  • Increment or decrement positions

Iterators are handled just like pointers.

CONTAINERS

As stated earlier, containers are objects that hold data of the same type.

The Standard Template Library (STL) defines ten containers, which are grouped into three categories.

These containers are used to store and organize data in memory efficiently.

  1. Sequence Containers

  1. Associative Containers

Containers supported by the STL

1. Vector

Key Characteristics of std::vector

A dynamic array. Allows insertions and deletions at back. Permits direct access to any element

  • Dynamic Resizing: Unlike regular arrays, you don’t need to know the size at compile time. It handles memory allocation internally.
  • Contiguous Memory: Elements are stored right next to each other in memory, just like a classic array.
  • Fast Access: You can jump to any element instantly using an index (Constant Time, O(1)).
  • Back Operations: Adding (push_back) or removing (pop_back) form the end is very efficient.

Random Access Iterators

The <vector> container provides Random Access Iterators. This is the most powerful types of iterator because it allows you to:

  1. Move forward and backward (++, - -).
  1. Jump to any position using arithmetic (e.g., it + 5)
  1. Use relational operators (<, >, ≤, ≥) to compare positions.

Code Example:

#include <iostream>
#include <vector> // Required header

int main(){
		// 1. Initializaiton
		std::vector<int> numbers = {10,20,30};
		
		// 2. Insertions at the back
		numbers.push_back(40);
		numbers.push_bakc(50);
		
		// 3. Direct access (Random Access)
		std::cout << "Element at index 2: " << numbers[2] << std::endl; // Output: 30
		
		// 4. Using Iterators
		std::vector<int>::iterator it = numbers.begin();
		
		// Jump forward by 3 positions instantly (Random Access property)
		it = it + 3;
		std::cout << "Elements afer jumping 3 spots: " << *it << std::endl; // Output: 40
		
		// 5. Deletion from the back
		numbers.pop_back(); // Removes 50
		
		// 6. Displaying final vector
		std::cout << "Final Vector: ";
		fir(int val : numbers){
				std::cout << val << " ";
		}
		return 0;
}

2. list

Key Characteristics of std::list

  • Non-Contiguous Memory: Elements are not stored side-by-side. Each element is wrapped in a node.
  • Efficient Insertions/Deletions: You can add or remove elements anywhere in the list in O(1) constant time, provided you already have a pointer/iterator to that location.
  • No Random Access: You cannot jump to list[5]. You must start at the beginning (or end) and follow the “links” one by one.
  • Memory Overhead: Each element stores two extra pointers (one for the next node, one for the previous node).

Bidirectional Iterators

The <list> container provides Bidirectional Iterators. This is a step below the Random Access iterators found in vectors.

  1. Can: Move forward (++) and backward(- -).
  1. Cannot: Use addition/subtraction to jump (e.g., it + 5 will cause a compiler error).
  1. Cannot: Use relational operators like < or >. You only check if two iterators are equal (==) or not (! =).

Code Example:

#include <iostream>
#include <list> // Required header

int main(){
		// 1. Initialization
		std::list<int> myList = {10, 20, 40};
		
		// 2. Insert anywhere (Efficient)
		auto it = myList.begin();
		it++; // Move to second position (points to 20)
		
		// Insert 15 BEFORE 20
		myList.insert(it,15);
		
		// 3. Bidirectional Movement
		it--; // Move back to 15
		it++; // Move forward to 20
		
		// 4. Deletion
		myList.pop_front(); // Removes 10 from the beginning
			myList.pop_back();// Removes 40 from the end
			
			// 5. Displaying the list
			std::cout << "List content: ";
			for(int val : myList){
					std::cout << val << " ";
			}
			return 0;
}

When to use std::list?

Use a list when you need to perform frequent insertions or deletions in the middle of a large collection, and you don’t need to access elements by their index.

3. deque

Key Characteristics of std::deque

  • Double-Ended: Unlike a vector, which is only fast at the back, a deque allows O(1) insertions and deletions at both the front and the back.
  • Segmented Memory: Unlike a vector’s single contiguous block, a deque uses a series of fixed-size memory block managed by a central map.
  • Random Access: Even though memory isn’t one single block, it still permits direct access to any element using an index (O(1)).
  • No Memory Relocation: Adding to the front doesn’t require shifting every other element (unlike a vector).

Random Access Iterators

The <deque> container provides Random Access Iterators, similar to a vector.

  1. Direct Jumps: You can use it + 5 to skip ahead.
  1. Comparison: You can use < and > to see which iterator comes first.
  1. Efficiency: While slightly slower than a vector’s iterator (due to the internal “map” logic), it is still considered constant time.

Code Example:

#include <iostream>
#include <deque> // Required header

int main(){
		// 1. Initialization
		std::deque<int> dq = {10, 20, 30};
		
		// 2. Insertions at BOTH ends - O(1)
		dq.push_back(40);  // {10, 20, 30, 40}
		dq.push_bakc(5);   // {5, 10, 20, 30, 40}
		
		// 3. Random Access - O(1)
		std::cout << "Element at index 2: " << dq[2] << std::endl; // Output: 20
		
		// 4. Using Random Access Iterators
		auto it = dq.begin() + 3;
		std::cout << "Element at iterator + 3: " << *it << std::endl; // Output: 30
		
		// 5. Deletions from both ends - O(1)
		dq.pop_front();  // Removes 5
		dq.pop_back();  // Removes 40
		
		// 6. Final output
		std::cout << "Final Deque: ";
		for(int x : dq) std::cout << x << " ";
		return 0;
}

When to use std::deque?

  • When you need a deque-like structure but still want to jump to the middle using an index.
  • When you need to insert/remove from both ends frequently
  • When you want to avoid the massive “reallocation and copy” cost a vector pays when it grows, as deques just allocate a new block.

4. set

A set is an associative container that stores unique elements following a specific order. It is typically

implemented as a Red-Black-Tree ( a type of self-balancing binary search tree), which ensures that elements are always sorted and searchable.

Key Characteristics of std::set

  • Uniqueness: Every element is a set in unique. If you try to insert a value that already exists, the set will simply ignore it.
  • Automatic Sorting: Because it uses a tree structure, searching for element takes logarithmic time (O(log n)), which is much faster than searching a vector or list.
  • Immutable keys: You cannot modify an element once it is in the set (because changing its value would break the sorting order). To “change” an element, you must delete it and insert the new value.

Bidirectional Iterators

The <set> container provides Bidirectional Iterators.

  1. Sequence: iterating from begin() to end() will give you the elements in sorted order.
  1. Movement: You can move forward (++) and backward(- -).
  1. No Random Access: You cannot use it + 5 because the nodes are linked in a tree, not stored in a contiguous block of memory.

Code Example:

#include <iostream>
#include <set> // Required header

int main(){
		// 1. Initialization (Notice duplicates are removed automatically)
		std::set<int>mySet = {40, 10, 20, 10, 30};
		
		// 2. Insertion
		mySet.insert(25);
		mySet.insert(40); // will be ignored because 40 already exists
		
		// 3. Rapid Lookup - O(log n)
		if(mySet.find(20) != mySet.end()){
			 std::cout << "20 is in the set!" << std::endl;
		}
		
		// 4. Deletion
		mySet.eraase(30);
		
		// 5. Displaying the set (Ouput will be sorted: 10 20 25 40)
		std::cout << "Set contents: ";
		for(int val: mySet){
			  std::cout << val << " ";
		}
		return 0;
}

When to use std::set?

  • When you need to ensure there are no duplicates.
  • When you need the data to be automatically sorted at all times.
  • When you need to check for the existence of an item quickly (O(log n)) without checking every single element.

5. multiset

A Multiset is almost identical to a std::set, with one major difference: it allows duplicate values.

If you insert the number 10 three times, the multiset will store all three instances.

Key Characteristics of std::multiset

  • Duplicates Allowed: Unlike a regular set, it does not check for uniqueness. It acts as a stored collection of all elements added.
  • Automatic Sorting: Like a set, it is typically implemented as a Red-Black Tree. Elements are kept in a specific order (usually ascending) at all times.
  • Rapid Lookup: It maintains O(log n) time complexity for searching, inserting, and deleting.
  • Contiguous Duplicates: In the internal tree structure, duplicate elements are stored as separate nodes and are guaranteed to be positioned next to each other during iteration.

Bidirectional Iterators

The <set> header provides Bidirectional iterators for multisets.

  1. Ordered Traversal: Iterating through the multiset will show all elements in sorted order, including duplicates side-by-side.
  1. Step-by-Step: You can use ++ to move to the next largest element and - - to move to the previous one.
  1. No Indexing: You cannot use myMultiset[2]. To reach the third element, you must increment an iterator twice.

Code Example:

#include <iostream>
#include <set>

int main(){
	// 1. Initialization (Duplicates are PRESERVED)
	std::multiset<int> ms = {40, 10, 20, 10, 10, 30};
	
	// 2. Insertion
	ms.insert(20); // ms now has two 20s
	
	// 3. Couting elements
	// Useful for multisets to see how many of a specific value exist
	std::cout << "Number of 10s: " << ms.count(10) << std::endl; // Output: 3
	
	// 4. Deletion
	// Note: ms.erase(10) would remove ALL 10s.
	// To remove only one, erase by iterator:
	ms.erase(ms.find(10));
	
	// 5. Displaying the multiset (Output: 10 10 20 20 30 40)
	std::cout << "Multiset contents: ";
	for(int val : ms){
			std::cout << val << " ";
	 }
	 return 0;
}

Important Note on Erasing

When using ms.erase(val), the multiset will remove all occurrences of the value. If you only want to remove one instance of a duplicate, you must find the iterator for that specific instance first: ms.erase(ms.find(val));

6. map

A map is an associative container that stores elements as a pair consisting of a Key and a Mapped Value. It is often referred to as a “dictionary” because you use a key to look up a value, just like you use a word to find its definition.

Key Characteristics of std::map

  • Key-Value Pairs: Each entry is a std::pair<const Key, Value>.
  • Unique Keys: Each key must be unique. If you try to insert a value with an existing key, it will either fail or overwrite the existing value (depending on the method used).
  • Automatic Sorting: Like std::set, a map is usually implemented as a Red-Black Tree. It stays sorted based on the keys.
  • One-to-One Mapping: Every unique key maps to exactly one value.

Bidirectional iterators

The <map> container provides Bidirectional Iterators.

  1. Accessing Data: Since each element is a pair, you access the key via it→first and the value via it→second.
  1. Sorted Order: Iterating from begin() to end() will traverse the keys in ascending order.
  1. No Random Access: You cannot jump to the “5th element” using it + 5. You must move step-by-step.

Code Example:

#include <iostream>
#include <map>
#include <string>

int main(){
	// 1. Initializaiton: Map <Key Type, Value Type>
	std::map<std::string, int> ageMap;
	
	// 2. Insertion
	ageMap["Alice"] = 25;     // Using operator[]
	ageMap.insert({"Bob", 30}]; // Using insert()
	ageMap.insert(std::make_pair("Charlie", 35));
	
	// 3. Unique Key Rule
	ageMap["Alice"] = 26; // Updates Alice's age t0 26; doesn't create a new entry
	
	// 4. Rapid Lookup - O(log n)
	std::string person = "Bob";
	if(ageMap.find(person) != ageMap.end()){
		 std::cout << person << " is " << ageMap[person] << " years old." << std::endl;
	}
	
	// 5. Displaying the Map (Sorted by name/key)
	std::cout << "\nAll entries:" << std::endl;
	for(auto it = ageMap.begin(); it != ageMap.end(); i++){
			// it->first is the key, it->second is the value
			std::cout << it->first << ": " << it->second << std::endl;
	}
	return 0;
	
}

7. multimap

A multimap is an associative container that behaves like a standard map but removes the restriction of unique key. This allows for one-to-many mapping, meaning a single key (like “User1”) can be linked to multiple different values (like “Order1”, “Order2”, “Order3”).

Key Characteristics of std::multimap

  • Duplicate Keys: You can have multiple entries with the exact same key.
  • Ordered Storage: Like std::map, it is typically implemented as a Red-Black-Tree. Elements are automatically sorted by their keys.
  • No operator[ ]: Because a key could refer to multiple values, myMultimap[”key”] would be ambiguous. Therefore, you must use insert or emplace().
  • Grouping: All entries sharing the same key are stored together in the internal tree structure.

Bidirectional Iterators

The <map> header provides Bidirectional Iterators for multimaps

  1. Pair Access: Each element is a std::par<const key, Value>. Use it→first for the key and it→second for the value.
  1. Sequential Access: You can move forward (++) and backward (- -) through the sorted keys.
  1. Range Finding: Since keys repeat, the multimap provides special functions like equal_range() to find all values associated with specific key.

Code Example:

#include <iostream>
#include <map> // Required header for both map and multimap
#include <string>

int main(){
		// 1. Initialization: Multimap <Key, Value>
		std::multimap<std::string, std::string> directory;
		
		// 2. Insertion (Must use insert, operator[ ] is not available)
		directory.insert({"HelpDesk", "555-0101"});
		directory.insert({"HelpDesk", "555-0102"}); // Same key, different value
		directory.insert({"Security", "555-9999"});
		
		// 3. Displaying all entries (Sorted by Key)
		std::cout << "Company Directory:" << std::endl;
		for(auto it = directory.begin(); it != directory.end(); ++it){
				std::cout << it->first << ": " << it->second << std::endl;
		}
		
		// 4. Finding all values for specific key
		std::cout << "\nSearching for HelpDesk number:" << std::endl;
		auto range = directory.equal_range("HelpDesk");
		
		for(auto it = range.first; it != range.second; ++it){
				std::cout << it->second << std::endl;
		}
		return 0;
}

8. stack

A Stack is a container adapter that provides a restricted data structure. it follows the LIFO (Last-In-First-Out) principle, meaning the last element added is the first one to be removed. Think of it like a physical stack of plates: you can only add new plate to the top, you can only take the top plate off.

Key Characteristics of std::stack

  • LIFO Logic: The most recently added item is the only one accessible
  • Container Adapter: It isn’t a standalone data structure; it “wraps” around other containers (by default, std::deque) to limit how you interact with the data.
  • Restricted Access: You cannot access elements in the middle or at the bottom. You only ever see the top.
  • No Iterators: This is a crucial distinction. Because a stack is designed for restricted access, the C++ Standard Library does not provide iterators for it. You cannot loop through a stack using begin() or end().

Code Example:

Since there are no iterators, the only way to see every element in a stack is to repeatedly look at the top and then remove it (pop) until the stack is empty.

#include <iostream>
#include <stack> // Required header


int main(){
		// 1. Initialization
		std::stack<int> s;
		
		// 2. Adding elements (Push)
		s.push(10); //[10]
		s.push(20); // [10, 20]
		s.push(30); // [10,20,30] -> 30 is at the top
		
		// 3. Accessing the top element
		std::cout << "Top element: " << s.top() << std::endl; // Output: 30
		
		// 4. Removing the top element (Pop)
		s.pop(); // Removes 30. Now 20 is at the top
		
		// 5. Checking size and empty status
		std::cout << "Stack size: " << s.size() << std::endl;
		
		// 6. "Processing" the stack (Since there are no iterators)
		std::cout << "Emptying stack: ";
		while(!s.empty()){
				std::cout << s.top() << " "; // Print the top
				s.pop();    // Remove the top to reach the next element
		}
		return 0;
}

9. queue

A Queue is a container adapter that follows the FIFO (First-In, First-Out) principle. This means the first element added to the queue is the first one to be removed. It mimics real-world scenarios like a line at a grocery store or a printer’s job queue.

Key Characteristics of std::queue

  • FIFO Logic: Elements are added at the back and removed from the front
  • Container Adapter: Like the stack, it wraps around an existing container (usually std::deque or std::list) to provide a specific interface.
  • Two-sided Access: You can look at the element at the very front (the next to be removed) and the element at the very back (the most recently added).
  • No Iterators: To maintain the strict FIFO rule, the C++ Standard Library does not allow you to iterate through the middle of a queue.

Example Code:

#include <iostream>
#include <queue> // Required header

int main(){
	// 1. Initialization
	std::queue<int> q;
	
	// 2. Adding elements (Push) - Enqueue
	q.push(10); // [10]
	q.push(20); // [10, 20]
	q.push(30); // [10, 20, 30]
	
	// 3. Accessing Front and Back
	std::cout << "Front: " << q.front() << std::endl; // Output: 10
	std::cout << "Back:  " << q.back() << std::endl; // Output: 30
	
	// 4. Removing the front element (Pop) -Dequeue
	q.pop(); // Removes 10. Now 20 is at the front.
	
	// 5. Processing the queue
	std::cout << "Remaining elements: ";
	while(!q.empty()){
			std::cout << q.front() << " "; // Access the current front
			q.pop();  // Remove it to reveal the next one
	}
	
	return 0;
	
}

Use Cases for Queue

  • Task Scheduling: Managing background tasks in an operating system.
  • Breadth-First Search (BFS): Exploring nodes level-by-level in a graph
  • Buffering: Holding data packets while they wait to be processed by a network.

10. priority-queue

A Priority Queue is a container adapter that provides a specialized queue where the element at the front is always the one with the highest priority (by default, the largest value), regardless of the order in which elements were added.

Key Characteristics of std::priority_queue

  • Sorted Access: It doesn’t follow a simple first-in order. Instead, it uses a Binary Heap (usually a Max-Heap) to keep the “greatest” element at the top.
  • Logarithmic Efficiency: Inserting an element or removing the top element takes O(log n) time, while looking at the top element is O(1).
  • Container Adapter: It typically wraps around a std::vector or std::deque
  • No Iterators: Like the stack and queue, it does not allow you to loop through the middle. You can only interact with the top element.

Code Example: Highest Value Priority

By default, std::priority_queue acts as a Max-Heap, meaning the largest number comes out first.

#include <iostream>
#include <queue> // Required header for both queue and priority_queue

int main(){
	// 1. Initialization (Default: Max-Heap)
	std::priority_queue<int> pq;
	
	// 2. Adding elements in random order
	pq.push(10);
	pq.push(50);
	pq.push(20);
	pq.push(40);
	
	// 3. Accessing the "Highest Priority" (TOP)
	// Even though 10 was pushed first, 50 will be at the top
	std::cout << "Top element: " << pq.top() << std::endl; // Output: 50
	
	// 4. Removing and Processing
	std::cout << "Priority order: ";
	while(!pq.empty()){
			std::cout << pq.top() << " "; // Access highest
				pq.pop();  // Remove highest, next highest moves to top
	}
	// Output: 50 40 20 10
	return 0;
}

Customizing Priority (Min-Heap)

if you want the smallest number to be the highest priority (a Min-Heap), you can change the template declaration:

// Syntax: priority_queue<Type, Container, Comparator>
std::priority_queue<int, std::vector<int>, std::greater<int> minPq;

Use Cases

  • Dijkstra’s Algorithm: Finding the shortest path in a graph
  • Operating System Scheduling: Running tasks with high priority levels first.
  • Data Compression: Huffman Coding uses priority queues to build trees.

Three major categories of containers

Sequence Containers

Sequence containers are the foundation of the C++ STL. As you noted, the main difference between std::vector , std::list , and std::deque isn’t what they can do, but how fast they do it based on their internal memory structure.

  1. Random Access Speed
  • Vector (Winner): Because it is a single contiguous block of memory, the CPU calculates the address of any element instantly using a simple formula: Address = Base + (Index x Size).
  • Deque: Also supports random access, but it is slightly slower than a vector because it has to look up the correct “memory block” in a central map first.
  • List: Does not support random access. To get to the 100th element, the computer must physically follow 99 pointers, making it very slow for large data.

The Formula Components

Imagine a vector of integers stored in memory:

Address = Base + (Index x Size)

  • Base: The memory address where the very first element (index 0) starts.
  • Index: The position you want to access (e.g., the 3rd element)
  • Size: The number of bytes each element occupies (e.g., an int is typically 4 bytes).

A Real-World Example

Suppose you have a std::vector<int> and:

  1. The Base address is 1000
  1. Each integer takes 4 bytes
  1. You want to access Index 3 (vec[3])

The Calculation:

Address = 1000 + (3 x 4)

Address = 1000 + 12

Address = 1012

The CPU immediately jumps to address 1012 to grab your data. It doesn’t matter if the vector has 10 elements or 10 million elements; the math takes the same amount of time This is why it is called Constant Time O(1).

While a std::deque (Double-Ended Queue) is very fast for adding elements to the ends, it is slightly slower than a std::vector for Random Access (jumping to an index). To understand why, we have to look at the Central Map.

What is the Central Map?

Unlike a vector, which is one single, continuous block of memory , a deque is a collection of multiple fixed-size blocks.

Imagine a series of “mini-arrays” scattered in memory. The Central Map is an array of pointers. Each pointer in this map points to one of those mini-arrays (blocks).

  • The Map: Keeps track of the order of the blocks.
  • The Blocks: Hold the actual data

Why it is slower than a Vector

The Address = Base + (Index x Size) formula we used for vectors is simple because there is only one block. For a deque, the computer has to do more work to find an element:

  1. Find the Block: It must calculate which block the index lives in (usually using division: Index/Block Size).
  1. Lookup in Map: it goes to the Central Map to find the memory address of that specific block.
  1. Find the Element: Once inside the correct block, it calculates the positions within that block (usually using modulo: Index%BlockSize)

In short: A vector access is 1 step (direct math). A deque access is 2 steps (find block in map + find element in block). This “double indirection” makes it slightly slower

  1. Insertion and Deletion Speed
  • Vector: Fast at the end. However, if you insert at the beginning, every single existing element must be “shifted” one spot to the right, which is very expensive (O(n)).
  • List (Winner for Middle): Since it uses pointers, you don’t shift data. You simply “unplug” two pointers and plug them into the new node. This is O(1) regardless of where you are in the list (if you have an iterator there)
  • Deque: Designed specifically to be fast at both the front and the back. It manages this by adding new memory blocks at either end without moving the existing elements.

  1. Memory & Cache Friendliness
    • Vector: The most “Cache Friendly”. Because elements are side-by-side, the CPU can load them into the fast cache memory all at once.
    • List: The least efficient. Since nodes are scattered everywhere in RAM, the CPU often has to wait for data to be fetched from the main memory (”Cache Misses”)

Summary: Which one to choose?

  1. Use std::vector by default for almost everything. It is the fastest for searching and accessing.
  1. Use std::list only if you are constantly adding/removing elements in the middle of very large collection.
  1. Use std::deque if you specifically need a deque where you add items to the front and the back.

Associative Containers

Associative containers are designed to support direct access to elements using keys. They are not sequential. There are four types of associative containers:

  • Set
  • Multiset
  • Map
  • Multimap

All four of these containers use an underlying structure called a Balanced Binary Search Tree (specifically a Red-Black Tree).

  • if you think of map as a dictionary, the Key is the word you look up, and the Mapped Value is the definition of that word.
  • How it works: Instead of a line, data is organized in “parent” and “child” nodes.
  • The Advantage: To find any element, the computer only needs to travel from the top of the tree to a leaf. In a tree with 1,000,000 items, it only takes about 20 steps (log2n) to find what you need.
  • The Disadvantage: Because elements are nodes scattered in memory and linked by pointers, you cannot use the simple math formula Address = Base + (Index x Size) for random access. This makes operations like container [5] either impossible or very slow (O(n)).

Derived Containers

The STL provides three derived containers namely, stack, queue, and priority_queue. These are also known as container adaptors.

  1. The Logic of Adapters

As you mentioned, these do not support iterators. This is intentional. If you could use an iterator to change the 3rd element in a stack, it would break the “Last-In, First-Out” rule. By hiding the iterators, the STL ensures you only use the data the “correct” way.

  1. The Three Adapters
    1. Stack (LIFO)
      • Default Underlying Container: std::deque
      • Analogy: A stack of cafeteria trays
      • Key Functions: push() (add to top), pop() (remove from top), top() (look at top).

    b. Queue (FIFO)

    • Default Underlying Container: std::deque
    • Analogy: A line at a bank.
    • Key Functions: push() (add to back), pop() (remove from front), front() (look at first in line).

    c. Priority Queue

    • Default Underlying Container: std::vector
    • Logic: The “largest” element (highest priority) is always at the front.
    • Internal Structure: It uses a Heap to keep the data organized.

A harsh reality of modern computing: CPU speed doesn’t matter if the CPU is constantly waiting for data from RAM.

  1. The “Memory Wall” Problem

Modern CPUs are incredibly fast, but RAM has not kept up.

  • The Gap: A CPU can perform hundreds of operations in the time it takes to fetch a single piece of data from the main memory (RAM).
  • The Solution: CPUs use a Cache (L1, L2, L3) to store all small amounts of data nearby.
  • The Catch: The cache only works if the CPU can predict what data you need next
  1. Contiguous vs. Scattered Memory

This is the core of the “List vs. Vector”

FeatureArrays / Vectors (Contiguous)Linked Lists / Python Objects (Scattered)
Memory LayoutElements are side-by-side in a single block.Elements are scattered across the heap.
CPU ActionFetches a "Cache Line" (e.g., 64 bytes). If you need index 1, index 2-8 are already in the cache.Fetches one node. To find the next, it must follow a pointer to a random new location.
ResultCache Hits: High speed, smooth execution.Cache Misses: The CPU "stalls" and waits for RAM.
  1. Why High-Level Languages are “Slow”

The text points out that languages like Python, JavaScript, and PHP are designed for developer convenience, not cache efficiency:

  • Everything is an Object: In Python, even a list of integers isn’t a simple block of numbers; it’s a list of pointers to objects scattered in memory.
  • Indirection: Every time you call a method or look up an attribute, the CPU has to “jump” to different memory addresses. Each jump is a potential cache miss.
  1. The Database Factor

Databases are the ultimate “Cache Miss Factory.” When you fetch data from a database:

  1. The DB hits the disk (slow)
  1. It sends data over a network (very slow)
  1. Your app turns that data into scattered objects (slows down the CPU)

Final Conclusion

The speed of modern software is less about “how many lines of code you write” and more about “how your data is laid in memory.”

If you want extreme performance:

  • Use flat data structures (Arrays, Structs, Vectors) instead of deeply nested objects or linked lists.
  • Process data in batches to take advantage of cache lines
  • Avoid “Pointer Chasing” (jumping from one object to another via pointers/references).

The Golden Rule: To keep a CPU happy, keep you data close together and keep it moving in a straight line.

How it works

For an input sequence

a1, a2, a3, a4

The output becomes:

a1,
a1 + a2,
a1 + a2 + a3,
a1 + a2 + a3 + a4

Example Code

#include <iostream>
#include <numeric>
#include <vector>
using namespace std;

int main() {
    vector<int> v = {1, 2, 3, 4};
    vector<int> res(v.size());

    partial_sum(v.begin(), v.end(), res.begin());

    for (int x : res)
        cout << x << " ";
}

Output

1 3 6 10
