Logical Errors-
    Logical errors occur due to poor understanding of the problem and solution procedure.
    Meaning:
        • The program compiles successfully
        • The program runs without crashing
        • But the output is wrong
    This happens because the logical (thinking/algorithm) use by the programmer is incorrect.
    Logical errors can be detected by using exhaustive debugging and testing procedures.

Syntactic Errors-
    Syntactic errors arise due to poor understanding of the programming language itself.
    They occur when rules (grammar) of the programming language are violated. if you do not write C++ code according to its syntax, the compiler will not understand it.
    These errors are detected by the compiler during compilation.
    Common Causes of Syntactic Errors
        1. Missing semicolon ;
        2. Missing or extra braces {}
        3. Wrong spelling of keywords
        4. Missing parentheses ()
        5. Incorrect variable declaration


Exhaustive Debugging and Testing Procedures
    Meaning:
        • carefully and repeatedly checking a program in all possible situations to find hidden errors, especially logical errors.

    🔧 Debugging
        • Finding where the program is going wrong
        • Checking values of variables step by step
        • Using breakpoints, dry run, and print statements
    
    🧪 Testing
        • Running the program with many different inputs
        • Checking expected output vs actual output
        • Testing normal, boundary, and extreme output
    
    🧠 Exhaustive
        • Not just one or twice
        • Testing every possible case
        • Trying all conditions and combinations

Example
Suppose you write a program to find the maximum of two numbers.
Exhaustive testing means:
    • Test with: 10, 5
    • Test with: 5, 10
    • Test with: -5, -10
    • Test with: 0, 0
    • Test with: INT_MAX, INT_MIN
If any test gives wrong output -> logical error found.


Exceptions are of two kinds (synchronous exceptions and asynchronous exceptions)
Exceptions in C++ -
    • Errors such as out-of-range index and overflow belong to the synchronous type of exceptions. These errors occur during program execution and are caused by faults in the program logic.

    • Errors that are caused by events beyond the control of the program, such as keyboard interrupts, power failure, or hardware failure, are called asynchronous exceptions.

    The exception handling mechanism in C++ is designed to handle only synchronous exceptions.

Synchronous Exceptions
    • Caused by your code
    • Occur at a predictable statement
    • Can be handled using try, throw, catch
Examples:
    • Array index out of range
    • Divide by zero
    • Overflow - is a condition in which the result of a computation exceeds the storage capacity of the data type used to hold it.
    • File open failure

Asynchronous Exceptions
    • Caused by external events
    • Not predictable
    • Not handled by C++ exception handling
Example:
    • Keyboard interrupt - A keyboard interrupt is an external signal generated by a user through the keyboard to abruptly interrupt or terminate a program during execution.
    • Power failure
    • Hardware crash



Error Handling in C++
The error handling code in C++ basically consists of two segments:
    1. One segment to detect errors and throw exceptions
    2. Another segment to catch the exceptions and take appropriate actions


1. Detecting errors and throwing exceptions
    • The program checks for an error condition
    • When an error is found, an exception is thrown using throw
Example:
    if(b==0)
        throw b;
    

2. Catching exceptions and take action
    • The thrown exception is caught using catch
    • Corrective action or error message is given
Example:
    catch(int x){
        cout << "Division by zero error";
    }



Throwing Mechanism in C++
When a program detects an error or abnormal condition that it wants to handle using exception handling, it throws an exception using the throw statement

Forms of throw statement
throw exception;
throw;
    (both are valid depending on situation)

1. throw exception
    • Used to generate (raise) a new exception
    • exception can be:
        • any data type (int, float, char, string, object, etc.)
        • A constant
        • Even an object not specifically meant for error handling
Example:
    throw 10; //integer exception
    throw "Error" //string literal
    throw obj;  //object

2. throw; (rethrow)
    • Used inside a catch block
    • Re-throws the same exception that was already caught
    • Does not specify an exception object
Example:
    catch(int e){
        cout << c;
        throw;  // rethrows the same exception
    }
    
Relation between throw and return
    • syntax of throw is similar to return
    • Difference:
        • return -> sends control back to calling function
        • throw -> sends control to catch block


Catch Block - Explanation

catch (type arg)
{
    // exception-handling code
}

The type specifies the type of exception that the catch block can handle.
The parameter arg is optional. if it is named, if can be used inside the exception-handling
code.

the exception-handling statements are written between the two braces {} of the catch block

When an exception is thrown, the catch statement catches the exception whose type matches the type of the catch argument. Once the exception is caught, the corresponding code block is executed.


After executing the handler, program control passes to the statement immediately following the catch block.

If an exception is thrown and not matching catch block is found due to type mismatch, the program will terminate abnormally.

It is important to note that a catch block is simply skipped if it does not match the type of the thrown exception
